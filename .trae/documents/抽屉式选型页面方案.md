# 新增「抽屉式选型」页面并接入主站

## Context（为什么做这件事）

现有站点 `index.html` 是**分步向导式**选型（一次只显示一步：系列→缸径→接线→…）。
用户希望再增加一个**「抽屉式」选型页面**（参考 airtac partcommunity 的 AQK 系列页：分类型逐层展开、可直接浏览与定位），并把它**关联到主页面**，让使用者既能用原来的向导式，也能用抽屉式；**其余选型逻辑保持不变**。

目标产出：多一个入口、多一种更直观的"逐层展开"浏览/选择方式，选型规则、型号构成、结果内容与主站完全一致。

## 待确认的假设（无法用 AskUserQuestion，请在批准时确认）

1. **覆盖范围**：默认新页面覆盖**全部系列**（与主站一致，共 18 个系列），只是 UI 换成抽屉式。
   —— 若只想覆盖 `AQK/BAQK`（销钉夹紧气缸，即参考链接那一条产品线），实现时把系列抽屉限定到该分组即可，改动很小。
2. **「抽屉式」形态**：理解为一组可展开/收起的「抽屉」垂直堆叠——每个抽屉 = 一个选型步骤；点一下展开选项，选定后自动收起并展开下一个抽屉（已选值显示在抽屉标题上）。这是对参考页"逐层展开"的等价实现。
3. **不改动现有选型逻辑**：`app.js` / `data.js` / `parser.js` 的选型规则**不动**。

## 实现方案

### 新增文件

1. **`selector-core.js`（新增，纯逻辑，无 DOM）**
   把 `app.js` 里与 DOM 无关的选型计算抽成一个可复用模块（内容与 `app.js` 现有实现一致，行为不变），挂到 `window.__selector`：
   - `rangeBores(group)`、`accessoryOptions(state)`、`candidateModels(state)`
   - `labelOf(key,val)`、`wireDisplay(state)`、`signalDisplay(state)`
   - `buildResult(state)`（含 `applyStroke`、`buildFull`、`buildSwitchCode`、`counterpartOld`）
   - `previewImgSrc(step,value,state)`、`switchBase(model)`
   - `getCustomerOptions(models, gen)`（连同 `normModel`/`modelBaseVariants`）
   - 复用常量：`STROKE_SERIES`、`SERIES_DESC`、`SERIES_LABEL`

   说明：为避免影响线上主站，`app.js` **保持原样不动**，本模块作为新页面的逻辑来源；如后续希望两页共用一份源码（去重），可再单独做一次无行为变更的抽取重构。

2. **`drawer.html`（新增页面）**
   结构与 `index.html` 同构，便于复用样式与组件：
   - `masthead` 头部、`sidetool` 左侧导航（三页：选型主页 / **抽屉式选型** / 型号解析，本页为 `is-current`）
   - 主区 = 抽屉堆叠容器（见下）
   - 结果区：复用 `index.html` 的 `.result` 结构（型号输出 `#modelOutput`、明细 `#resultGrid`、`#customerSelect`、`#result3dLink`/第三方数模预览 + `3d-viewer.html?m=…&single=1`、`3d数模下载`、`复制完整型号`、`重新选型`、灯箱 `#lightbox`）

3. **`drawer.js`（新增，页面脚本）**
   抽屉式 UI 交互 + 状态机，**步骤与选项完全按现有规则动态生成**（`buildSteps` 的等价逻辑）：
   - 抽屉顺序：系列 → 缸径 → 接线方式 →（三线时）信号类型 → 标准型/增强型 →（ACQ/SDA、TCM、TCL 时）真实行程 → 出线方式 →（直接出线时）线缆长度／（QD 时）接头材质 → 安装附件
   - 交互：点选项 → 该抽屉标记完成并收起 → 自动展开下一个；点击已完成抽屉标题 → 展开该步并清除其后所有选择（等价于 `app.js` 的 `gotoStep`）；顶层「系列」抽屉默认展开
   - 出线方式/接头材质/标准型-增强型 三处保留右侧**效果图 + 点击放大灯箱**（复用 `previewImgSrc`）
   - 出线方式/接头材质为"选完点下一步确认"的步骤，保持原行为（`metal` 需点「下一步」）
   - 选完最后一步 → 用 `buildResult` 出结果（完整型号、对应标准型、客户型号切换、3D 预览与下载）

### 修改文件

4. **`styles.css`（追加，不改现有规则）**
   新增 `.drawer` / `.drawer__head` / `.drawer__body` / `.drawer__value` / `.drawer.is-open` / `.drawer.is-done` 等样式，复用现有 CSS 变量（`--accent`、`--amber`、`--panel` 等）与 `.option`/`.btn`/`.result` 组件；保持现有移动端适配（`styles.css` 已有媒体查询）。

5. **`index.html`（仅加导航与入口，不动选型逻辑）**
   - 在 `.sidetool__nav`（`index.html:34-37`）追加 `<a class="sidetool__link" href="drawer.html">抽屉式选型</a>`
   - 在选型卡顶部或页面说明处加一个轻量入口链接/按钮指向 `drawer.html`

6. **`second.html`（仅加导航）**
   同样在 `.sidetool__nav` 追加第三项，保持全站导航一致。

## 复用要点（避免重复实现）

- 数据：`data.js` 的 `GROUPS` / `BORE_STANDARD`（新页面直接引入）
- 数模：`models3d.js` 的 `MODELS_3D` 与 `3d-viewer.html?m=…&single=1`（沿用现有约定）
- 型号解析能力：`parser.js` 已导出 `window.__parseModel` 等（新页面如需解析可直接复用）
- 样式组件：`.card` / `.option` / `.btn` / `.result` / `.wire-preview` / `.lightbox` 全部复用

## 验证方式（端到端）

1. 本地静态服务：项目内起一个静态服务器（Node 内置 http，监听如 5500），打开 `http://localhost:5500/drawer.html`。
2. 用浏览器子代理逐项核对：
   - 抽屉式选型：依次选到结果，核对生成的完整型号与主站在**相同选择**下完全一致（抽样 ACQ/SDA 三线 NPN 增强型 + 直接出线 03m、AQK 两线 M12QD(SE) 金属、PB 必选附件等边界用例）。
   - 结果区：完整型号、对应标准型、客户型号切换、3D 预览、下载按钮是否正常；无结果时不出现残留。
   - 交互：点击已完成的抽屉能回退并清空后续选择；灯箱放大可用。
3. 回归：打开 `index.html` 与 `second.html`，确认**原有向导式选型与型号解析一切照旧**（因为 `app.js` 未改动），且左侧导航新增入口可跳转。
4. 移动端/小屏：确认抽屉式页面在窄屏下不错位（沿用现有媒体查询）。
